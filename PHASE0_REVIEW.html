02Tizim qanday ishlaydi

Bitta markaziy Orchestrator ishlarni boshqaradi. Agentlar bir-birini chaqirmaydi: vazifa oladi → ishlaydi → bazaga yozadi → SUCCESS/FAILED/NEEDS_REVIEW qaytaradi (SPEC §4).

Mijoz (IG DM)→ Conversation Engine→ Requirements AI→ Specification AI→ Mijoz tasdiqi (1 marta)→ Spec Auditor→ Coding Agent→ Code Checker (runtime)→ Team Panel / inson→ Narx + muddat (inson)→ Yetkazish

🧩 Modular monolith — 4 jarayon

api (REST + webhook + preview) · worker (orchestrator + agentlar) · coderunner (build + Playwright tekshiruv) · panel (Next.js). Bitta Postgres, bitta Caddy. Mikroservis yo'q.

⚙️ Navbat = Postgres jadvali

Holat o'zgarishi va keyingi ish bitta tranzaksiyada yoziladi → ish yo'qolmaydi va ikki marta bajarilmaydi (SPEC §4, §41). Redis shart emas; kelajakda BullMQ'ga almashtirish izolyatsiya qilingan.

🔒 §10A bazada majburlangan

CLIENT_CONFIRMED statusi faqat mijozning haqiqiy xabar ID siga bog'langan holda yoziladi — CHECK constraint. AI taxmini hech qachon "mijoz tasdiqladi" bo'lib ko'rinmaydi (SPEC §53).

🧪 Simulator kanal — kritik qaror

Meta App Review haftalab davom etadi. Shuning uchun P1–P7 bosqichlari Meta'siz ham to'liq ishlaydi va test qilinadi: simulyator kanali orqali butun zanjir haydaladi (D-013).

04Loyiha holatlari (state machine)

SPEC §3 dagi 23 holat aynan saqlandi. Har bir o'tish guard (shart) va majburiy yon-effektlar bilan jadvalda yozilgan — docs/05.

NEW → INTAKE → REQUIREMENTS_IN_PROGRESS → REQUIREMENTS_COMPLETE
    → SPEC_GENERATING → CLIENT_REVIEW → (CLIENT_CHANGES_REQUESTED ⇄ qayta)
    → CLIENT_APPROVED → SPEC_AUDIT → READY_FOR_BUILD → BUILDING
    → CODE_AUDIT → TEAM_REVIEW → PRICE_PENDING → DEADLINE_PENDING
    → IN_DEVELOPMENT → READY_FOR_DELIVERY → COMPLETED
    + BLOCKED / FAILED  (har qanday bosqichda to'xtatish, sabab bilan)

♻️ Cheksiz looplar to'xtatiladi

Spec audit va Code check — maksimum 3 urinish; so'ng BLOCKED + inson uchun vazifa. Hisoblagichlar bazada saqlanadi, restart ularni nolga qaytarmaydi (§21, §26).

✋ Inson faqat kerak joyda

Narx/muddat faqat inson tomonidan (API AI yozishini rad etadi); critical xavfsizlik topilsa avtomatika darhol to'xtaydi (§30, §42).

07Asosiy xatarlar (qisqacha)

A1 · Meta tasdiqi kechikishi yuqori

Yechim: simulyator kanali, App Review'ni 1-haftada topshirish, FB-Login zaxira adapteri.

B4 · Checker noto'g'ri PASS berishi o'rta

Yechim: dalil talab qilinadi (test natijalari, skrinshot, konsol loglar); ishga tushira olmasa — FAIL.

B5 · Prompt-injection o'rta

Yechim: mijoz matni faqat DATA blokida, agentlarda yon-effekt tool yo'q, chiqish JSON-sxema bilan tekshiriladi.

C3 · Build'lar resurs yeyishi o'rta

Yechim: coderunner alohida konteyner, 1 CPU/900MB/15daq limit, bir vaqtda ≤2 build.

To'liq reyestr (A1–A9, B1–B9, C1–C9, D1–D4): docs/16_known_risks.md.
